# Termijn voor Supabase-verzoeken — implementatieplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Elk Supabase-verzoek uit de browser telt na 10 s zonder antwoord als netwerkfout. Een afstreping die onzeker verstuurd is, wordt bij ongedaan maken ook op de server heropend.

**Architecture:** Een pure functie `metTermijn` omwikkelt `fetch` en breekt verzoeken naar de Supabase-URL na 10 s af met een `AbortError`. Een client-plugin met `order: -25` zet die wikkel op `window.fetch`, vóór de supabase-plugin. `isNetwerkfout` herkent het afgebroken verzoek. `verstuurWachtrij` meldt welk item onzeker is. `useOfflineVoorraad` houdt de onzekere id's in het geheugen bij, en `ongedaanMakenInWachtrij` heropent zo'n item ook op de server. De voorraadpagina en de offline-pagina gebruiken die gedeelde functie.

**Tech Stack:** Nuxt 4, @nuxt/ui 4, @nuxtjs/i18n 10, @nuxtjs/supabase 2, Playwright, Vitest.

**Spec:** `docs/superpowers/specs/2026-10-04-termijn-design.md`

## Global Constraints

- **Elke "Falsificeer"-stap is verplicht.** Breng de wijziging aan, zie de genoemde test ROOD worden, draai terug en zie hem GROEN worden. Blijft een test groen bij zijn falsificatie, dan herschrijf je de test; je verzwakt nooit de falsificatie. Een commit bevat nooit een gefalsificeerde toestand.
- **De termijn is `SUPABASE_TERMIJN_MS = 10_000`**, ook in de e2e-tests. Er komt geen kortere termijn voor tests en geen omgevingsvariabele.
- **Afbreken gebeurt met een eigen `AbortController` en `abort()` zonder reden.** Geen `AbortSignal.timeout`: dat geeft een `TimeoutError`, en die probeert postgrest-js bij een GET opnieuw.
- **`metTermijn` zet zijn signaal op het `init`-object dat hij krijgt.** De herhaallus in `node_modules/@nuxtjs/supabase/dist/runtime/utils/fetch-retry.js` stopt alleen als `init.signal.aborted` waar is.
- **Een netwerkfout is:**
  - `navigator.onLine === false`;
  - een rauwe `TypeError`;
  - een object met `name === 'AbortError'` en een `code` die geen string is (een `DOMException` heeft een numerieke code);
  - of een object met `code === ''` en een `message` die begint met `'TypeError: '` of `'AbortError: '`.
- **Onzeker** is een afstreping waarvan de laatste poging faalde terwijl het toestel online was en de fout geen niet-lege string als `code` had (spec §5).
- **De opslagversie blijft `1`.** Onzeker leeft alleen in het geheugen.
- **Elke nieuwe i18n-sleutel gaat in alle drie de locales.** Frans spreekt aan met *vous*, en een afstreping heet daar "retrait".
- **Commentaar, testnamen en meldingen in het Nederlands.**
- **Stop een eigen `nuxt dev` op poort 3000 vóór e2e.** Draai de volledige e2e-suite met `--workers=2`.
- **Elke commit eindigt met de Co-Authored-By-regel van je eigen harness.** Commits worden via 1Password gesigneerd. Faalt dat onduidelijk, meld dan BLOCKED; omzeil het signeren nooit.

## Wat al gemeten is

- **De vorm van een afgebroken verzoek.** postgrest-js (`node_modules/@supabase/postgrest-js/dist/index.mjs`, de `.catch((fetchError) => …)` in `PostgrestBuilder`) maakt van een afgebroken fetch:

  ```ts
  { code: '', message: `${fetchError.name}: ${fetchError.message}`, hint: 'Request was aborted (timeout or manual cancellation)' }
  ```

  Zijn eigen `fetchWithRetry` herhaalt nooit bij `name === 'AbortError'`.
- **De herhaallus van `@nuxtjs/supabase`.** Die (`…/utils/fetch-retry.js`) probeert elke fetchfout tot drie keer, tenzij `init?.signal?.aborted`.
- **De plugin-volgorde.** `node_modules/nuxt/dist/index.mjs` (`internalOrderMap`) geeft `enforce: 'pre'` orde −20. De supabase-plugin heeft `enforce: 'pre'` en vraagt bij het opstarten de sessie op. `order: -25` sorteert de termijn-plugin ervóór.
- **Supabase-js roept `fetch` pas bij het verzoek aan.** `@nuxtjs/supabase` geeft zijn eigen `fetchWithRetry` mee, en die roept bij elke poging de globale `fetch` aan. Wie `window.fetch` vervangt, raakt dus elk verzoek.
- **De voorraadpagina** toont bij een fout in de eerste lading `<UAlert … :description="t('householdSettings.error')" />`.
- **De Playwright-testtimeout** is 90 s (`playwright.config.ts`). Een test met één of twee termijnen past daarin.

const SUPABASE = 'https://abc.supabase.co'

/** Een fetch die nooit antwoordt, maar wel afbreekt op het signaal dat ze krijgt. */
function hangendeFetch() {
  const aanroepen: { invoer: RequestInfo | URL; init: RequestInit | undefined }[] = []
  const fetch = ((invoer: RequestInfo | URL, init?: RequestInit) => {
    aanroepen.push({ invoer, init })
    return new Promise<Response>((_, reject) => {
      init?.signal?.addEventListener('abort', () => reject(init.signal!.reason))
    })
  }) as typeof globalThis.fetch
  return { fetch, aanroepen }
}

/** Het signaal dat de omwikkelde fetch kreeg bij aanroep i. */
function signaal(aanroepen: { init: RequestInit | undefined }[], i = 0): AbortSignal {
  const s = aanroepen[i]?.init?.signal
  if (!s) throw new Error(`aanroep ${i} kreeg geen signaal`)
  return s
}

beforeEach(() => {
  vi.useFakeTimers()
})

afterEach(() => {
  vi.useRealTimers()
})

describe('metTermijn', () => {
  // AbortError en geen TimeoutError: postgrest-js herhaalt een AbortError
  // nooit, een TimeoutError bij een GET wel, tot drie keer.

    const { fetch, aanroepen } = hangendeFetch()

```ts
/**
 * Een termijn voor Supabase-verzoeken, zonder Nuxt. Zie
 * docs/superpowers/specs/2026-10-04-termijn-design.md §3.
 */

/** Spec §2: ruim genoeg voor een trage verbinding die werkt. */
export const SUPABASE_TERMIJN_MS = 10_000

function urlVan(invoer: RequestInfo | URL): string {
  if (typeof invoer === 'string') return invoer
  if (invoer instanceof URL) return invoer.href
  return invoer.url
}

/**
 * Een fetch die verzoeken naar `voorvoegsel` na `ms` afbreekt.
 *
 * Met een eigen AbortController en abort() zonder reden: dat geeft een
 * AbortError, en die herhaalt postgrest-js nooit. AbortSignal.timeout geeft
 * een TimeoutError, en die herhaalt het bij een GET tot drie keer.
 *
 * De timer wordt niet gewist: na een afgerond verzoek doet abort() niets, en
 * loopt het lezen van het antwoord nog, dan breekt dat ook af.
 *
 * Wijzigt `init` bewust: de herhaallus van @nuxtjs/supabase
 * (runtime/utils/fetch-retry.js) stopt alleen als zijn eigen
 * `init.signal.aborted` waar is.
 */
export function metTermijn(fetch: typeof globalThis.fetch, voorvoegsel: string, ms: number): typeof globalThis.fetch {
  return (invoer, init) => {
    if (!urlVan(invoer).startsWith(voorvoegsel)) return fetch(invoer, init)

    const controller = new AbortController()
    setTimeout(() => controller.abort(), ms)

    const eigen = init?.signal ?? (typeof invoer === 'object' && !(invoer instanceof URL) ? invoer.signal : null)
    if (eigen) {
      if (eigen.aborted) controller.abort()
      else eigen.addEventListener('abort', () => controller.abort(), { once: true })
    }

    if (init) init.signal = controller.signal
    return fetch(invoer, { ...init, signal: controller.signal })
  }
}
```

```ts
/**
 * Is dit een netwerkfout? postgrest-js vangt een mislukte fetch op en geeft
 * `{ code: '', message: `${fetchError.name}: ${fetchError.message}` }` terug
 * (node_modules/@supabase/postgrest-js/dist/index.mjs). Een mislukte fetch is
 * een TypeError ("Failed to fetch", "NetworkError…", "Load failed"). Een
 * verzoek dat de termijn afbrak (app/utils/termijn.ts), is een AbortError.
 */
export function isNetwerkfout(oorzaak: unknown, online: boolean): boolean {
  if (!online) return true
  if (oorzaak instanceof TypeError) return true
  if (!isRecord(oorzaak)) return false
  // De afgebroken fetch zelf, nog niet ingepakt door postgrest-js. Een
  // DOMException heeft een numerieke code, een databasefout een string.
  if (oorzaak.name === 'AbortError' && typeof oorzaak.code !== 'string') return true
  const { code, message } = oorzaak
  return code === '' && typeof message === 'string' && (message.startsWith('TypeError: ') || message.startsWith('AbortError: '))
}
```

 * antwoord tegen tot `vrijgeven()`. De pagina breekt het verzoek af op de

  const { vrij, vrijgeven } = slot()

    let gelukt = false
    schrijf((o) => {
      const k = leesKopie(o)

      if (!eigenaar) return

  async function ongedaanMakenInWachtrij(item: VoorraadItem): Promise<Ongedaanuitkomst> {
